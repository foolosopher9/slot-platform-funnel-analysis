# Глава 1. Данные

## 1.1. Источник

Исследование выполнено на синтетическом датасете **«Online Slot Games - Players, Sessions & Spins»** (автор — Monika Mitrovic), опубликованном на Kaggle.

| Параметр | Значение |
|---|---|
| Ссылка | https://www.kaggle.com/datasets/monikamitrovic/online-slot-games-players-sessions-and-spins |
| Версия | 1 (333 МБ, три CSV-файла) |
| Дата скачивания | 4 октября 2026 |
| Лицензия | CC0: Public Domain |
| Природа данных | Программная симуляция активности игроков в онлайн-слотах. Реальных игроков и данных оператора нет |
| Назначение по описанию автора | Практика SQL-анализа поведения игроков |

**Масштаб:**

- 8 000 игроков;
- 46 690 игровых сессий;
- 4 646 999 спинов;
- 60 слотов.

**Окно измерений — 120 дней:** сессии начинаются с 1 октября 2025 по 28 января 2026 года, последние завершаются в первые минуты 29 января. Игроки регистрировались с 1 по 30 октября 2025 года. Все метки времени хранятся в UTC без привязки к часовому поясу игрока.

Валюта ставок и выигрышей в датасете не указана. Суммы приводятся в условных единицах.

## 1.2. Структура и поля

Датасет состоит из трёх таблиц. У каждой есть первичный ключ (`player_id`, `session_id`, `spin_id`). Сессия ссылается на игрока, спин — на сессию и дополнительно напрямую на игрока.

```
players ───< sessions ───< spins
   └────────────────────────<┘   (spins.player_id)
```

- **players → sessions:** у игрока может быть много сессий или ни одной.
- **sessions → spins:** в сессии много спинов.
- **players → spins:** прямая ссылка `spins.player_id` дублирует связь через сессию. Она упрощает расчёты на уровне игрока; совпадение с игроком сессии проверено (1.3).

Данные загружаются в PostgreSQL скриптом `scripts/load.sh`: он создаёт таблицы (`01_schema.sql`), загружает CSV, а затем создаёт первичные и внешние ключи и индексы (`02_keys_indexes.sql`). Успешное создание ключей подтверждает отсутствие дубликатов идентификаторов и ссылок на несуществующие записи.

### Поля

| Таблица | Поле | Описание |
|---|---|---|
| **players** | `player_id` | Идентификатор игрока |
| | `signup_ts` | Дата и время регистрации |
| | `country` | Страна, заявленная игроком (10 стран) |
| | `acquisition_channel` | Канал привлечения: affiliate, organic, paid_search, paid_social, referral |
| | `device_pref` | Предпочитаемое устройство: mobile / desktop |
| | `os` | Операционная система: android / ios / windows / mac |
| **sessions** | `session_id` | Идентификатор сессии |
| | `player_id` | Ссылка на игрока |
| | `start_ts`, `end_ts` | Начало и окончание сессии |
| | `duration_sec` | Длительность в секундах |
| | `device_id_hash` | Хэш идентификатора устройства |
| | `ip_hash` | Хэш IP-адреса |
| | `ip_country` | Страна, определённая по IP |
| | `geo_mismatch` | 1, если `ip_country` не совпадает с `players.country` |
| | `num_spins` | Число спинов в сессии |
| | `avg_bet`, `max_bet` | Средняя и максимальная ставка в сессии |
| | `spins_per_min` | Темп игры: `num_spins / (duration_sec / 60)` |
| **spins** | `spin_id` | Идентификатор спина |
| | `session_id` | Ссылка на сессию |
| | `player_id` | Ссылка на игрока |
| | `ts` | Время спина |
| | `slot_id` | Идентификатор слота (slot_001–slot_060) |
| | `slot_volatility` | Волатильность слота: low / med / high |
| | `bet_amount` | Ставка |
| | `win_amount` | Выигрыш |
| | `feature_buy` | 1, если спин — всплеск ставки в стиле покупки бонуса (feature buy) |

**Два уточнения к полям:**

1. **`feature_buy` не означает покупку бонуса.** По описанию автора, флаг отмечает спин с резко повышенной ставкой, похожий на покупку бонусной функции. Самой механики (бонусного раунда, фриспинов) в данных нет. В отчёте такие спины называются **всплесками ставки**.
2. **`geo_mismatch` и `feature_buy` в исходных CSV хранятся как 0/1.** При загрузке они приводятся к типу `boolean`.

## 1.3. Проверки качества

Перед анализом данные проверены на полноту, уникальность, связи, согласованность и допустимые значения. Запросы — `03_quality_checks.sql`, по одному на каждую группу из таблицы.

| Группа | Что проверено | Результат |
|---|---|---|
| Полнота | Количество строк; NULL во всех используемых полях | 0 пропусков |
| Уникальность и связи | Дубликаты идентификаторов; сессии без игрока, спины без сессии, сессии без спинов; `spins.player_id` совпадает с игроком сессии | 1 сессия без спинов, остальное — 0 |
| Время | `end_ts ≥ start_ts`; `duration_sec` = `end_ts − start_ts`; спины внутри своей сессии; сессии внутри окна измерений и после регистрации | 0 нарушений |
| Согласованность | `num_spins`, `avg_bet`, `max_bet` и `spins_per_min` совпадают с фактическими спинами; `geo_mismatch` совпадает со своим определением | 0 расхождений |
| Допустимые значения | Ставки > 0, выигрыши ≥ 0; категории из ожидаемых списков; у каждого слота один уровень волатильности; ОС соответствует устройству | 0 нарушений |

**Единственная находка — одна сессия без спинов** (0,002% сессий, группа «Уникальность и связи»). Она учитывается в числе сессий как вход без игры, но исключается из метрик ставок и темпа игры фильтром `num_spins > 0`.

**Итог.** Анализ выполняется на полном наборе данных; исходные таблицы не изменяются, фильтры применяются в запросах анализа. Такая чистота характерна для синтетических данных (ограничение 1 в 1.5). Главная особенность данных — не ошибки, а тяжёлый хвост ставок, поэтому средние значения приводятся только для справки (1.4, «Концентрация ставок»).

В хвосте два эффекта:

1. **Разовые всплески у многих игроков.** Самые крупные отдельные ставки — почти всегда всплески, и их делали около 1 600 разных игроков. Один всплеск заметно увеличивает оборот игрока, даже если в остальном он играет как все.
2. **Небольшая группа крупных игроков.** По суммарному обороту игроки сильно неравны: 69 человек (1% игроков со ставками) дают четверть оборота, а каждый из топ-10 в среднем ставит примерно в 75 раз больше, чем средний игрок.

**Крупные ставки не удаляются и не обрезаются.** Невозможных значений нет (1.3), а 93% крупнейших ставок — помеченные генератором всплески, то есть заложенное поведение, а не ошибки записи.

Следствия для анализа: сегменты сравниваются по медианам, а не средним (несколько крупных игроков сдвигают среднее, но почти не влияют на медиану), а оборот на игрока имеет смысл считать в двух вариантах — со всплесками и без них.

## 1.5. Ограничения

**Природа данных**

1. **Синтетические данные.** Датасет создан как учебная симуляция. Поведенческие паттерны в нём более гладкие, чем в реальном iGaming, поэтому выводы нельзя переносить на реальный бизнес напрямую. Отчёт демонстрирует метод анализа, а не факты о рынке.
2. **Время суток задано генератором.** Метки хранятся в UTC без часового пояса игрока. По описанию автора, синхронный во всех странах всплеск активности в 18:00 — артефакт генерации. Это подтверждается в 1.4: кроме всплеска, с 4 до 10 утра UTC сессии не начинаются вовсе. Анализ времени суток и дней недели в отчёте не проводится.
3. **Жёсткие границы сессий.** Длительность всегда от 60 до 5 400 секунд, спинов не более 600. Это собственное наблюдение: вероятно, это ограничения генератора, а не поведение игроков.

**Период наблюдения**

4. **Разный срок наблюдения игроков.** Регистрации идут с 1 по 30 октября, а данные заканчиваются 28 января. Игрок, зарегистрированный 1 октября, наблюдается около 120 дней, а зарегистрированный 30 октября — около 90. Метрики «за весь период» поэтому смешивают поведение игрока с длительностью наблюдения: при прочих равных у ранних игроков больше сессий и оборота. Медианные даты регистрации в каналах и странах почти совпадают (1.4), поэтому сегменты смещены слабо, но для строгого сравнения метрики игроков нужно считать за одинаковое окно после регистрации.

**Чего нет в данных**

5. **Финансовые транзакции.** Нет депозитов, выводов, бонусов. Реальные LTV, ARPU и маржу оператора посчитать нельзя; доступны только оборот (ставки) и GGR (ставки минус выигрыши).
6. **Стоимость привлечения.** Нет расходов на каналы. Выводы о каналах касаются качества приведённых игроков, а не окупаемости.
7. **Механика бонусов.** `feature_buy` фиксирует только всплеск ставки. Был ли бонусный раунд и чем он закончился, неизвестно.
8. **Метаданные слотов.** Известны только `slot_id` и волатильность. Нет провайдера, тематики и заявленного RTP. Слотов высокой волатильности всего 4, поэтому выводы о них менее надёжны.
9. **CRM и ответственная игра.** Нет коммуникаций, акций, статуса лояльности, лимитов и самоисключения. Проблемного игрока нельзя отличить от обычного, поэтому любые выводы о рисках — гипотезы.
10. **География IP.** `ip_country` содержит только 10 стран присутствия оператора. Игры из других стран, через VPN из третьих стран и т. п. в данных нет, поэтому `geo_mismatch` описывает только перемещения между этими 10 рынками.
11. **Валюта.** Не указана; суммы сравниваются только между собой.

**Свойства распределений**

12. **Тяжёлый хвост ставок.** Оборот сильно сконцентрирован: 0,1% ставок дают 23,2% оборота, а 1% игроков — 26,4% (1.4, «Концентрация ставок»). Поэтому средний и суммарный оборот сегмента зависят от нескольких крупных игроков: попадание одного-двух из них в канал или страну может перевернуть сравнение. Отчёт сравнивает сегменты по медиане, то есть делает выводы о типичном игроке. Рейтинг сегментов по суммарной выручке на этих данных ненадёжен: место канала или страны в нём может определить попадание туда двух-трёх крупных игроков.
