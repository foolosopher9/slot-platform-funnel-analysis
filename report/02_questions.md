# Глава 2. Постановка задачи и исследовательские вопросы

## 2.1. Бизнес-контекст

Рассматривается оператор онлайн-казино, работающий на нескольких европейских рынках (Сербия, Германия, Великобритания, Франция и др.) и привлекающий трафик через пять каналов (affiliate, organic, paid_search, paid_social, referral).

Анализ «заказывают» две внутренние роли, каждая из которых ждёт ответов на свои вопросы.

**Маркетинг** хочет понять, какие каналы и страны приводят самых активных и много ставящих игроков, чтобы определить, в какие источники трафика вкладываться в первую очередь.

**Комплаенс** следит за признаками нарушения правил платформы: игрой из другой юрисдикции, чем указана в аккаунте (`geo_mismatch`), мультиаккаунтингом (одно устройство у разных игроков), автоматизированной игрой (аномальный темп спинов) и шерингом аккаунта (пересекающиеся сессии). Такие случаи создают регуляторные риски и риск злоупотреблений.

## 2.2. Цели

### Цель 1. Маркетинг

| Поле | Содержание |
|---|---|
| Заказчик | Команда маркетинга |
| Решение | Как распределить бюджет привлечения между каналами и странами |
| Что даёт исследование | Для каждого канала — вердикт: кандидат на увеличение бюджета, оставить как есть или пересмотреть. Для каждой страны — кандидат на изменение бюджета, который нужно подтвердить на следующей когорте игроков |
| Как измеряется качество игроков | Две метрики за 90 дней после регистрации: доля активных игроков (3+ сессий) и медианный оборот играющего игрока (1+ сессия) |
| Правило вердикта | Обе метрики выше остальных → кандидат на увеличение бюджета; обе ниже → пересмотреть (сократить бюджет или сменить таргетинг); остальные сочетания → оставить как есть |
| Ограничение | Стоимости привлечения в данных нет, поэтому вердикт — «кандидат», а не окончательное решение о бюджете |

### Цель 2. Комплаенс

| Поле | Содержание |
|---|---|
| Заказчик | Команда комплаенса |
| Решение | Каким сегментам игроков отдавать приоритет при мониторинге нарушений |
| Что даёт исследование | Для каждого признака нарушения — сегмент, в котором он встречается чаще, и правило: где мониторить усиленно, а где хватит единых правил. Для шеринга аккаунта — список игроков для прямой проверки |
| Признаки нарушений | geo_mismatch — игра из другой юрисдикции; общее устройство — мультиаккаунтинг; темп выше p99 — автоматизированная игра; пересекающиеся сессии — шеринг аккаунта |
| Сегменты | Устройство (`device_pref`) и канал привлечения. Каждый выбран, потому что для него есть механизм нарушения: поездки → mobile, реферальный бонус → referral, скрипты → desktop |
| Как изучается шеринг аккаунта | Описательно, без сравнения сегментов: каждый случай пересекающихся сессий подозрителен сам по себе и проверяется независимо от сегмента, поэтому сравнение сегментов не меняет решения |
| Ограничение | Признаки косвенные: они указывают на подозрение, а не доказывают нарушение. Данных о подтверждённых нарушениях нет |

## 2.3. Окно наблюдения

Все метрики игрока считаются за первые 90 дней после регистрации. В расчёт входят сессии с `sessions.start_ts < players.signup_ts + 90 дней` и спины с `spins.ts < players.signup_ts + 90 дней`.

**Почему окно одинаковое.** Без общего окна ранние игроки получают преимущество в сессиях и обороте просто за счёт более долгого наблюдения (ограничение 4 в 1.5).

**Почему 90 дней.** Это самое длинное окно, которое полностью наблюдается у каждого из 8 000 игроков: последняя регистрация 30 октября 23:54, последние сессии начинаются 28 января. Более длинное окно снова сделало бы условия игроков неравными, более короткое отбросило бы данные без причины.

## 2.4. Принятые решения

1. **Все 8 000 игроков входят в расчёт.** Игроки без сессий в окне получают нулевой оборот и считаются неактивными.
2. **Активный игрок — игрок с 3 и более сессиями в окне.** Порог N = 3 — медиана числа сессий на игрока за 90 дней. Она посчитана один раз по всем 8 000 игрокам, включая игроков без сессий, а не отдельно по каналам или странам, и зафиксирована до расчётов по исследовательским вопросам. Так порог нельзя подогнать под нужный результат.
3. **Играющий игрок — игрок с 1 и более сессией в окне.** Медианный оборот считается только по играющим игрокам.
4. **Различие признаётся по 99% доверительному интервалу.** Сегмент сравнивается со всеми остальными сегментами: для долей — разница долей, для медиан — разница медиан с бутстрэпом по игрокам.
5. **Оборот считается со всплесками ставки.** Расчёт без всплесков — проверка устойчивости вывода.

## 2.5. Исследовательские вопросы

### Вопрос 1. Активность по каналам

| Поле | Содержание |
|---|---|
| Вопрос | Отличается ли доля активных игроков в каждом канале от остальных каналов? |
| Тип | Проверка |
| Гипотеза | organic, affiliate и paid_search выше: игрок сам искал казино. paid_social ниже: импульсный клик по рекламе. referral ниже остальных каналов: игрок пришёл за бонусом, а не за игрой. |
| Метрика | Доля игроков с 3+ сессиями за 90 дней после регистрации; все 8 000 игроков. Сравнение: разница долей «канал − остальные каналы», 99% ДИ. |
| Решение | Вместе с вопросом 2: оба «выше» → кандидат на увеличение бюджета; оба «ниже» → пересмотреть (сократить бюджет или сменить таргетинг); остальные сочетания → оставить как есть. |

### Вопрос 2. Оборот по каналам

| Поле | Содержание |
|---|---|
| Вопрос | Отличается ли медианный оборот играющего игрока за 90 дней в каждом канале от остальных каналов? |
| Тип | Проверка |
| Гипотеза | organic, affiliate и paid_search выше: игрок сам искал казино и готов ставить больше. paid_social ниже: после импульсного клика интерес к игре слабый. referral ниже остальных каналов: игрок пришёл за бонусом, а не за игрой. |
| Метрика | Медианный оборот игрока (сумма `bet_amount`) за 90 дней после регистрации; только игроки с 1+ сессией за 90 дней. Сравнение: разница медиан «канал − остальные каналы», бутстрэп по игрокам, 99% ДИ. Основной расчёт со всплесками ставки, проверка устойчивости — без них. |
| Решение | Вместе с вопросом 1: оба «выше» → кандидат на увеличение бюджета; оба «ниже» → пересмотреть (сократить бюджет или сменить таргетинг); остальные сочетания → оставить как есть. |
